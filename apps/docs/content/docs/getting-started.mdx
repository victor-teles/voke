After this page you have a Voke API that runs on your machine, passes its tests, and deploys to AWS Lambda with one command. You need [Bun](https://bun.sh) installed.

<Callout type="info" title="Voke is not published yet">
  The published names (`voke`, `@voke/*`) are not final. The steps below work
  once Voke is published. Until then, [try it from the
  repository](#try-it-from-the-repository).
</Callout>

## Create, run and deploy

<Steps>
<Step>

### Create the project

```bash
voke create my-api
```

`voke create` writes the starter files into `./my-api`, runs `bun install` in it, and prints the next steps:

```txt
Created my-api in ./my-api

Next steps:
  cd my-api
  bun run dev        # local API on http://localhost:3000
  bun test
  bun run deploy     # deploy the dev stage to AWS
```

Pass `--no-install` to skip `bun install`. The printed steps then include a `bun install` line after `cd my-api`.

</Step>
<Step>

### Run it locally

```bash
cd my-api
bun run dev
```

`bun run dev` runs `voke dev`. It starts the API with hot reload on `http://localhost:3000`. Open `http://localhost:3000/health` to get `{"data":{"ok":true}}`.

</Step>
<Step>

### Run the tests

```bash
bun test
```

The starter test sends `GET /health` to the Gateway through `createTestClient()` from `@voke/testing`. No server or AWS account is needed.

</Step>
<Step>

### Deploy

```bash
bun run deploy
```

`bun run deploy` runs `voke deploy --stage dev`. It builds the project, deploys a CloudFormation stack named `my-api-dev`, and prints the stack outputs, with the API URL (`ApiUrl`) first. The first deploy in an account and region also creates a `voke-bootstrap` stack that holds the deployment artifacts.

<Callout type="info" title="Deploying needs AWS credentials">
  Use an AWS profile, an SSO login, or credentials in environment variables. Run
  `voke doctor` to check Bun, the config, the project and your AWS credentials.
  See [Troubleshooting](/docs/guides/troubleshooting) when a check fails.
</Callout>

</Step>
<Step>

### Remove the stage

```bash
bun run remove
```

`bun run remove` runs `voke remove --stage dev`. It asks you to type `my-api-dev` to confirm, then deletes the stack and its resources. Tables, buckets and secrets are kept with their data; Voke lists each one with the command that deletes it.

</Step>
</Steps>

## The generated project

<Files>
  <File name="voke.config.ts" />
  <Folder name="src" defaultOpen>
    <File name="index.ts" />
    <Folder name="routes" defaultOpen>
      <File name="health.ts" />
    </Folder>
  </Folder>
  <Folder name="test" defaultOpen>
    <File name="api.test.ts" />
  </Folder>
  <File name="package.json" />
  <File name="tsconfig.json" />
  <File name="README.md" />
  <File name=".gitignore" />
</Files>

| File                   | What it holds                                                                                                                                    |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| `voke.config.ts`       | The project name, the entrypoint and the Provider (`provider: aws()`). The Provider is set only here, and `deploy`, `synth` and `local` need it. |
| `src/index.ts`         | The entrypoint. It declares the Functions and exports the Gateway.                                                                               |
| `src/routes/health.ts` | The `GET /health` route, made with the Route Builder.                                                                                            |
| `test/api.test.ts`     | A `bun test` test that calls `GET /health` through `@voke/testing`.                                                                              |
| `package.json`         | The dependencies and the scripts `build`, `clean`, `deploy`, `dev`, `local`, `remove`, `synth`, `test` and `typecheck`.                          |
| `tsconfig.json`        | Strict TypeScript settings for Bun. `bun run typecheck` uses it.                                                                                 |
| `README.md`            | The four commands you use most.                                                                                                                  |
| `.gitignore`           | Ignores `node_modules`, `dist`, `.voke`, `.env*` and `coverage`.                                                                                 |

[Concepts](/docs/concepts) explains the entrypoint, the Gateway and the other terms.

## Try it from the repository

Until Voke is published, run the example API in the Voke repository.

<Steps>
<Step>

### Clone the repository and run the tests

```bash
git clone https://github.com/victor-teles/voke.git
cd voke
bun install
cd examples/hello-api
bun test
```

`bun test` runs the example's tests against the Gateway in process. It needs no server, Docker or AWS account.

</Step>
<Step>

### Run the example API locally

The example's `voke.config.ts` declares a DynamoDB table and an SQS queue, so `voke dev` needs them running on your machine first. That uses the AWS Emulator in Docker, and bootstrapping it needs the AWS CLI:

```bash
bunx voke local start       # builds the emulator image once, then starts it
bunx voke local bootstrap   # creates the table and the queue
bun run dev                 # serves the API on http://localhost:3000
```

<Callout type="warn" title="Start the emulator first">

Without the emulator running, `voke dev` stops with `AWS Emulator is not running`.

</Callout>

Stop the API with `Ctrl+C` and the emulator with `bunx voke local stop`. See [Local AWS](/docs/guides/local-aws).

</Step>
</Steps>
