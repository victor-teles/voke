After reading this page you can define a **Function** with `fn()`, register it with `createFunctions()`, and call it from code and tests with `functions.invoke(...)`.

## Define and invoke a Function

A Function is a named unit of compute that Voke deploys as one AWS Lambda function. An invokable Function has a **Function Contract**: an `input` schema for the payload and an `output` schema for the result. Voke validates both on every call.

```ts title="src/index.ts" twoslash
// @filename: voke.config.ts
import { aws } from "@voke/aws";
import { defineConfig } from "voke";

export default defineConfig({ name: "users-api", provider: aws() });
// @filename: src/index.ts
// ---cut---
import { schema } from "@voke/schema";
import { createFunctions, fn, voke } from "voke";
import config from "../voke.config";

const user = schema.object({
  id: schema.string(),
  name: schema.string(),
});

export const functions = createFunctions({
  getUser: fn({
    input: schema.object({ id: schema.string() }),
    output: user,
    handler: async (payload) => ({ id: payload.id, name: "Ada" }),
  }),
});

export default voke(functions, { config });

const result = await functions.invoke("getUser", { id: "usr_1" });
//    ^?
```

| Call                             | What it does                                                                                                                                  |
| -------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| `fn()`                           | Declares the Function. The handler receives the payload after the `input` schema parsed it, so `payload.id` is typed as `string`.             |
| `createFunctions()`              | Builds the **Function Registry**. Each object key becomes the Function's identity in your project.                                            |
| `voke(functions, { config })`    | Creates the **Gateway**. It also activates the registry for local invocation (see [Activate the registry](#activate-the-registry)).           |
| `functions.invoke(key, payload)` | Validates the payload, runs the handler, validates the result, and returns it. The key and the payload are type-checked against the contract. |

The `input` and `output` fields accept any Standard Schema validator. This page uses `@voke/schema`; Zod works the same way. See [Schemas and validation](/docs/guides/schemas).

### Functions without input

Leave out `input` when a Function takes no payload. Call it with the key only:

```ts title="src/index.ts" twoslash
// @filename: voke.config.ts
import { aws } from "@voke/aws";
import { defineConfig } from "voke";

export default defineConfig({ name: "users-api", provider: aws() });
// @filename: src/index.ts
// ---cut---
import { schema } from "@voke/schema";
import { createFunctions, fn, voke } from "voke";
import config from "../voke.config";

const functions = createFunctions({
  countUsers: fn({
    output: schema.object({ total: schema.number() }),
    handler: () => ({ total: 42 }),
  }),
});

voke(functions, { config });

const { total } = await functions.invoke("countUsers");
```

### The handler context

A handler receives a second argument, the invoke context:

| Field           | Description                                                                                |
| --------------- | ------------------------------------------------------------------------------------------ |
| `functionName`  | The Function's deployed name: `name` when set, otherwise the registry key.                 |
| `resource(key)` | The binding value of a resource the Function links in `resources`. See below.              |
| `trace`         | The trace metadata passed with `invoke(..., { trace })`.                                   |
| `variables`     | The Function's Runtime Variables. See [Runtime Variables](/docs/guides/runtime-variables). |

### Use a resource

A Function lists the resources it uses from `voke.config.ts` in `resources`, by resource key. Every
Function builder takes it. The handler reads a linked resource with `context.resource(key)`, and the
Function's IAM role gets access to the linked resources and no others:

```ts twoslash
import { schema } from "@voke/schema";
import { fn } from "voke";

// ---cut---
const archiveUser = fn({
  input: schema.object({ id: schema.string() }),
  output: schema.object({ table: schema.string() }),
  resources: ["usersTable"],
  handler: (payload, context) => ({ table: context.resource("usersTable") }),
});
```

See [Resources and bindings](/docs/guides/resources#read-a-resource-from-a-function).

## Activate the registry

Local invocation needs an activated Function Registry, and `voke(functions, { config })` activates it. If you call `functions.invoke(...)` before a Gateway exists, the call rejects with a `VokeConfigError` (code `CONFIG_ERROR`):

```txt
Local Function invocation requires Gateway activation. Call voke(functions) before invoking local functions.
```

In tests, import the module that calls `voke(...)`, or call `voke(functions, { config })` in the test setup before you invoke. You can create more than one Gateway for the same registry with the same project name, stage and region. A Gateway with a different name, stage or region throws `Function Registry is already activated with a different Gateway context`.

## Invoke options

`functions.invoke(key, payload, options)` accepts these options:

| Option          | Type                                       | Default   | Description                                                                                                        |
| --------------- | ------------------------------------------ | --------- | ------------------------------------------------------------------------------------------------------------------ |
| `mode`          | `"sync"` or `"async"`                      | `"sync"`  | `"async"` returns `{ accepted: true }` at once and runs the Function in the background.                            |
| `trace`         | object of string, number or boolean values | none      | Metadata the handler reads from `context.trace`.                                                                   |
| `timeoutMs`     | `number`                                   | none      | Rejects with an `InvokeError` with code `TIMEOUT` when the call takes longer.                                      |
| `retries`       | `number`                                   | `0`       | Extra attempts after a failed attempt. `retries: 2` runs the Function at most three times.                         |
| `onAsyncError`  | `(error: InvokeError) => void`             | none      | Receives the error of a failed `"async"` call. Without it, Voke logs the message with `console.error`.             |
| `executionName` | `string`                                   | none      | Names the execution of a [Durable Function](/docs/guides/durable-functions), so starting it is idempotent.         |
| `runtime`       | `"local"` or `"aws"`                       | `"local"` | `"local"` runs the handler in the current process. `"aws"` calls the deployed Lambda through `transport`.          |
| `transport`     | `InvokeTransport`                          | none      | Required when `runtime` is `"aws"`. `createAwsLambdaInvokeTransport()` from `@voke/aws` calls Lambda's Invoke API. |

```ts title="src/index.ts" twoslash
// @filename: voke.config.ts
import { aws } from "@voke/aws";
import { defineConfig } from "voke";

export default defineConfig({ name: "users-api", provider: aws() });
// @filename: src/index.ts
// ---cut---
import { schema } from "@voke/schema";
import { createFunctions, fn, voke } from "voke";
import type { InvokeError } from "voke";
import config from "../voke.config";

const functions = createFunctions({
  sendWelcomeEmail: fn({
    input: schema.object({ userId: schema.string() }),
    output: schema.object({ sent: schema.boolean() }),
    handler: (payload, context) => {
      console.info("request", context.trace.requestId, payload.userId);
      return { sent: true };
    },
  }),
});

voke(functions, { config });

const sent = await functions.invoke(
  "sendWelcomeEmail",
  { userId: "usr_1" },
  { retries: 2, timeoutMs: 5000, trace: { requestId: "req_1" } }
);

const queued = await functions.invoke(
  "sendWelcomeEmail",
  { userId: "usr_1" },
  {
    mode: "async",
    onAsyncError: (error: InvokeError) =>
      console.error(error.code, error.message),
  }
);
// queued is { accepted: true }
```

<Callout type="warn" title="A local timeout does not stop the handler">
  A local timeout rejects the call, but the handler runs until it returns.
</Callout>

The default runtime is `"local"` unless the environment variable `VOKE_INVOKE_RUNTIME` is `aws`. With `runtime: "aws"`, Voke invokes the Lambda by its deployed name, and `mode: "async"` uses Lambda's `Event` invocation type.

### Invoke errors

A failed call rejects with an `InvokeError` from `voke`. Its `code` tells you what failed:

| Code                     | Cause                                                                          |
| ------------------------ | ------------------------------------------------------------------------------ |
| `INVALID_PAYLOAD`        | The payload failed the `input` schema. `error.issues` lists each problem.      |
| `INVALID_RESULT`         | The handler's return value failed the `output` schema.                         |
| `TIMEOUT`                | The call took longer than `timeoutMs`.                                         |
| `MISSING_FUNCTION`       | The key is not an invokable Function, for example an HTTP or SQS Function.     |
| `MISSING_TRANSPORT`      | `runtime` is `"aws"` and no `transport` was given.                             |
| `LOCAL_FUNCTION_FAILED`  | An `"async"` local call threw. Delivered to `onAsyncError`.                    |
| `TRANSPORT_FAILED`       | The transport threw, for example a network or credentials failure.             |
| `TRANSPORT_STATUS_ERROR` | The deployed Lambda returned a function error or a status code of 400 or more. |

An error that the handler throws in a `"sync"` local call rejects the call unchanged.

## Registry key and deployed name

The registry key is the identity you use in code: `functions.invoke("getUser", ...)`, typed route calls and Lambda handler names all use it. The optional `name` field on `fn()` changes only the deployed Lambda function name.

```ts title="src/index.ts" twoslash
// @filename: voke.config.ts
import { aws } from "@voke/aws";
import { defineConfig } from "voke";

export default defineConfig({ name: "users-api", provider: aws() });
// @filename: src/index.ts
// ---cut---
import { schema } from "@voke/schema";
import { createFunctions, fn, voke } from "voke";
import config from "../voke.config";

const user = schema.object({ id: schema.string() });

const functions = createFunctions({
  getUser: fn({
    name: "production-user-reader",
    input: user,
    output: user,
    handler: (payload) => payload,
  }),
});

voke(functions, { config });

// Still invoked by its registry key.
await functions.invoke("getUser", { id: "usr_1" });
```

Without `name`, the deployed Lambda is named `<project name>-<stage>-<registry key>`, for example `users-api-dev-getUser`. With `name`, it is that value in every stage. Error messages such as `Invalid payload for production-user-reader` use the deployed name.

<Callout type="warn" title="Reserved registry keys">
  The keys `invoke`, `route` and `sendEvent` are reserved. `createFunctions()`
  throws when you use one.
</Callout>

## Set timeout and memory per Function

Every Function gets its timeout and memory from `runtime` in `voke.config.ts`: 15 seconds and 1024 MB by default. Override them for one Function with `synthesis`:

```ts title="src/index.ts" twoslash
// @filename: voke.config.ts
import { aws } from "@voke/aws";
import { defineConfig } from "voke";

export default defineConfig({
  name: "reports-api",
  provider: aws(),
  runtime: { memory: 512, timeout: 10 },
});
// @filename: src/index.ts
// ---cut---
import { schema } from "@voke/schema";
import { createFunctions, fn, voke } from "voke";
import config from "../voke.config";

const functions = createFunctions({
  buildReport: fn({
    input: schema.object({ month: schema.string() }),
    output: schema.object({ url: schema.string() }),
    synthesis: { memory: 2048, timeout: 120 },
    handler: (payload) => ({ url: `https://example.com/${payload.month}.pdf` }),
  }),
});

export default voke(functions, { config });
```

`synthesis.timeout` is in seconds and `synthesis.memory` is in MB. When the AWS Provider synthesizes the stack, it rejects a timeout outside 1-900 seconds and memory outside 128-10240 MB. See the [configuration reference](/docs/reference/config).

<Callout type="warn" title="HTTP routes allow 30 seconds at most">
  A Function that serves HTTP routes cannot have a timeout above 30 seconds. See
  [HTTP routes](/docs/guides/http-routes).
</Callout>

## Other kinds of Functions

`fn()` declares an invokable Function: other code calls it by key. The same registry also holds:

- HTTP route Functions, declared with `http()`. See [HTTP routes](/docs/guides/http-routes).
- SQS Event Source Functions, declared with `sqs()` from `@voke/aws`. See [SQS events](/docs/guides/sqs-events).
- Request Authorizer Functions, declared with `requestAuthorizer()` from `@voke/aws`. See [Authorizers](/docs/guides/authorizers).

`functions.invoke(...)` calls only invokable Functions. Use `functions.route(...)` for HTTP routes and `functions.sendEvent(...)` for SQS Functions.
