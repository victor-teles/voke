After reading this page you can serve HTTP routes from a Function, validate what each request carries, return the response you want, and call the routes from tests.

## Declare routes

`http()` declares a Function that serves HTTP routes. You build each route with the **Route Builder**, `route`, from `voke`:

```ts title="src/index.ts" twoslash
// @filename: voke.config.ts
import { aws } from "@vokejs/aws";
import { defineConfig } from "voke";

export default defineConfig({ name: "users-api", provider: aws() });
// @filename: src/index.ts
// ---cut---
import { schema } from "@vokejs/schema";
import { createFunctions, http, route, voke } from "voke";
import config from "../voke.config";

const functions = createFunctions({
  users: http({
    routes: [
      route.get("/users/:id", {
        params: schema.object({ id: schema.string() }),
        handler: (request) => ({ id: request.params.id, name: "Ada" }),
      }),
      route.post("/users", {
        body: schema.object({ name: schema.string().min(1) }),
        handler: (request) => ({ id: "usr_2", name: request.body.name }),
      }),
    ],
  }),
});

export const gateway = voke(functions, { config });

const response = await gateway.request("/users/usr_1");
console.log(response.status, await response.json());
// 200 { data: { id: "usr_1", name: "Ada" } }
```

`voke dev` serves these routes on `http://localhost:3000`. When you deploy, the AWS Provider creates an API Gateway HTTP API with one route per declaration, and every route of the `users` Function runs in the same Lambda.

The Route Builder has one method per HTTP verb: `route.get`, `route.post`, `route.put`, `route.patch`, `route.delete`, `route.head` and `route.options`. `route.route(method, path, definition)` takes the verb as an argument.

Path parameters use the `:name` syntax. A method and path pair must be unique across all Functions in the registry, or `voke(...)` throws a `VokeConfigError`.

<Callout type="warn" title="No body schema on GET and HEAD">
  A `GET` or `HEAD` route cannot declare a `body` schema. The Route Builder
  throws when it does.
</Callout>

## Read the request

The handler receives a request object and the invoke context (see [Functions](/docs/guides/functions#the-handler-context)):

| Field     | Content                                                                                                           |
| --------- | ----------------------------------------------------------------------------------------------------------------- |
| `params`  | Path parameters. The output of the `params` schema when you declare one.                                          |
| `query`   | Query string values as a plain object. The output of the `query` schema when you declare one.                     |
| `headers` | Request headers as a plain object with lower-case names. The output of the `headers` schema when you declare one. |
| `body`    | The output of the `body` schema. `undefined` when the route has no `body` schema.                                 |
| `raw`     | The original `Request`. `request` is the same object.                                                             |
| `auth`    | The Route Auth Context set by an authorizer. See [Authorizers](/docs/guides/authorizers).                         |

Without a schema, `query` and `headers` are typed `Record<string, string | undefined>`:

```ts twoslash
import { createFunctions, http, route } from "voke";

const functions = createFunctions({
  search: http({
    routes: [
      route.get("/search", {
        handler: (request) => ({
          page: Number(request.query.page ?? "1"),
          requestId: request.headers["x-request-id"],
          term: request.query.q ?? "",
        }),
      }),
    ],
  }),
});
```

Declare a `query` or `headers` schema to validate and convert them. The handler then gets the schema's output:

```ts twoslash
import { schema } from "@vokejs/schema";
import { createFunctions, http, route } from "voke";
import { z } from "zod";

const functions = createFunctions({
  search: http({
    routes: [
      route.get("/search", {
        query: z.object({ page: z.coerce.number().default(1) }),
        headers: schema.object({ "x-tenant": schema.string() }),
        handler: (request) => ({
          page: request.query.page,
          tenant: request.headers["x-tenant"],
        }),
      }),
    ],
  }),
});
```

These rules apply to `query` and `headers`:

- Values are strings. Convert them in the schema or in the handler.
- A repeated query key or header is one string, joined with a comma: `?tag=a&tag=b` gives `"a,b"`. Split on `,` and trim each part. Cookies are joined with `; `.
- Header names are lower-case. A `@vokejs/schema` `headers` object with a name in another case makes `voke(...)` throw a `VokeConfigError`.
- A `@vokejs/schema` object rejects a query parameter it does not declare, with the issue `Unexpected property`.
- A `headers` schema checks the headers it names. Clients, proxies and API Gateway add other headers, so a strict object schema from another validator, such as `z.strictObject`, cannot be used for headers.
- `request.raw` is the original `Request`, with the exact URL and the `Headers` object.

When a `params` schema is a `@vokejs/schema` object, its keys must match the parameters in the path. `voke(...)` throws a `VokeConfigError` at startup when they differ.

### The body

A `body` schema means a JSON body. Voke reads the body only when the route declares a `body` schema:

- When the request has no body or an empty body, the schema receives `undefined`, whatever the content type.
- When the media type is `application/json` or ends in `+json`, such as `application/vnd.api+json`, Voke parses the body as JSON. Parameters such as `charset` and the case of the type do not matter.
- When the JSON does not parse, Voke answers `400` with the issue `Malformed JSON` at the path `["body"]`.
- When the body has any other content type, or none, Voke answers `415`.

To accept text, a form or binary data, declare no `body` schema and read `request.raw`, for example with `await request.raw.formData()`.

An `output` schema on a route validates the handler's return value before Voke serializes it. It does not apply when the handler returns a `Response`. The handler's return type is also checked against the `output` schema at compile time: a handler that returns the wrong shape does not compile. A `Response` is always allowed and never validated.

## Return a response

Voke turns the handler's return value into the HTTP response:

| Handler returns | Response                                       |
| --------------- | ---------------------------------------------- |
| A value         | `200` with the JSON body `{ "data": <value> }` |
| `undefined`     | `204` with no body                             |
| A `Response`    | That response, unchanged                       |

To set another status or an error body, return a response built with `@vokejs/http`:

```ts twoslash
import { created, error, noContent, ok } from "@vokejs/http";
import { schema } from "@vokejs/schema";
import { createFunctions, http, route } from "voke";

const functions = createFunctions({
  orders: http({
    routes: [
      route.post("/orders", {
        body: schema.object({ sku: schema.string() }),
        handler: (request) => created({ id: "ord_1", sku: request.body.sku }),
      }),
      route.get("/orders/:id", {
        handler: (request) =>
          request.params.id === "ord_1"
            ? ok({ id: "ord_1" }, { headers: { "cache-control": "no-store" } })
            : error("Order not found", {
                code: "ORDER_NOT_FOUND",
                status: 404,
              }),
      }),
      route.delete("/orders/:id", {
        handler: () => noContent(),
      }),
    ],
  }),
});
```

| Helper                     | Status                    | Body                                                      |
| -------------------------- | ------------------------- | --------------------------------------------------------- |
| `ok(data, init?)`          | `200`                     | `{ "data": data }`                                        |
| `created(data, init?)`     | `201`                     | `{ "data": data }`                                        |
| `noContent(init?)`         | `204`                     | none                                                      |
| `error(message, options?)` | `options.status` or `400` | `{ "error": { "code", "details", "issues", "message" } }` |

`init` is a standard `ResponseInit`, so you can set `status` and `headers`. `error` accepts `code`, `details` and `issues` in its options and leaves out the fields you do not set. The same helpers are available as `response.ok`, `response.created`, `response.noContent` and `response.error`.

## Errors

Voke answers some requests without running your handler, or after it fails. Every body it writes is an **Error Envelope**, `{ "error": { "code", "message", "issues"?, "details"? } }`:

| Situation                                                 | Status  | `code`                   | `message`                                         |
| --------------------------------------------------------- | ------- | ------------------------ | ------------------------------------------------- |
| `body`, `params`, `query` or `headers` fails its schema   | `400`   | `INVALID_REQUEST`        | `Invalid body`, `Invalid params`, …               |
| The JSON body does not parse                              | `400`   | `INVALID_REQUEST`        | `Invalid body`                                    |
| A body with another content type than JSON                | `415`   | `UNSUPPORTED_MEDIA_TYPE` | `Unsupported content type: send application/json` |
| No route matches the method and path                      | `404`   | `NOT_FOUND`              | `Route not found`                                 |
| The handler throws an `HTTPException` with a status < 500 | its own | from the status          | its message                                       |
| The handler throws anything else                          | `500`   | `INTERNAL_SERVER_ERROR`  | `Internal server error`                           |

A request with the wrong method gets the `404` too: the deployed HTTP API has one route per declared method and path, so it never answers `405`. On AWS, API Gateway answers a request that matches no route with its own body, before any Function runs.

The `500` covers a return value that fails the `output` schema and an `InvokeError` from a nested `functions.invoke(...)` call. The client never sees their issues or the Function name.

A request failure lists its issues. Each issue has a `message` and a `path`. The path starts with the request part, for example `["body", "name"]`:

```txt
{
  "error": {
    "code": "INVALID_REQUEST",
    "message": "Invalid body",
    "issues": [
      { "message": "Expected string length to be at least 1", "path": ["body", "name"] }
    ]
  }
}
```

When a handler fails, Voke logs one JSON line with the error's name, message and stack, and the issues of a failed `output` schema. The client gets the generic body above.

<Callout type="info" title="The original message stays on the server">

The original message never reaches the client in a deployed stage. Under `voke dev` only, the body also carries it in `error.details.message`, so you can see it while you develop.

</Callout>

### Throw an HTTP error

To stop a handler with a client error, throw an `HTTPException` from Hono. Voke answers with its status, a `code` for the status, such as `UNAUTHORIZED` or `TOO_MANY_REQUESTS`, and its message:

```ts twoslash
import { HTTPException } from "hono/http-exception";
import { createFunctions, http, route } from "voke";

const functions = createFunctions({
  reports: http({
    routes: [
      route.get("/reports/:id", {
        handler: (request) => {
          if (request.headers["x-tenant"] === undefined) {
            throw new HTTPException(401, { message: "Sign in first" });
          }

          return { id: request.params.id };
        },
      }),
    ],
  }),
});
```

An `HTTPException` created with a `res` returns that response unchanged. One with a status of `500` or more keeps its status, but the body is the generic `Internal server error`.

## Allow browser requests with CORS

CORS is off by default. Set `api.cors` in `voke.config.ts` to let browsers on other origins call the API:

```ts title="voke.config.ts" twoslash
// @filename: voke.config.ts
// ---cut---
import { aws } from "@vokejs/aws";
import { defineConfig } from "voke";

export default defineConfig({
  name: "users-api",
  provider: aws(),
  api: {
    cors: {
      origins: ["https://app.example.com"],
      methods: ["GET", "POST"],
      headers: ["content-type", "authorization"],
      credentials: true,
      maxAgeSeconds: 600,
    },
  },
});
```

`cors: true` allows every origin, method and header, without credentials. In the object form, fields you leave out default to `["*"]` for `origins`, `methods` and `headers`, and to `false` for `credentials`.

<Callout type="warn" title="Credentials need explicit origins">
  With `credentials: true` you must list explicit origins.
</Callout>

The same settings drive the local Gateway and the deployed HTTP API's CORS configuration, so a preflight request gets the same answer locally and on AWS.

## Call routes from tests

You can call a route in two ways.

`functions.route(method, path, input)` calls the handler directly. The method and path must match a declared route. `input` accepts `params`, `body`, `query`, `headers` and `auth`, and the route's schemas validate them. `query` and `headers` are plain objects; header names are lower-cased, as on a real request. It returns the handler's return value (after the `output` schema), not an HTTP response. When the handler returns a `Response`, `functions.route(...)` resolves to that `Response`, although its static type is the `output` type. It does not run authorizers or middleware.

`gateway.request(path, init)` sends a real `Request` through the Gateway: routing, CORS, authorizers, validation, serialization and error handling all run. It returns a `Response`.

```ts title="src/index.ts" twoslash
// @filename: voke.config.ts
import { aws } from "@vokejs/aws";
import { defineConfig } from "voke";

export default defineConfig({ name: "users-api", provider: aws() });
// @filename: src/index.ts
// ---cut---
import { schema } from "@vokejs/schema";
import { createFunctions, http, route, voke } from "voke";
import config from "../voke.config";

const functions = createFunctions({
  users: http({
    routes: [
      route.get("/users/:id", {
        params: schema.object({ id: schema.string() }),
        handler: (request) => ({ id: request.params.id, name: "Ada" }),
      }),
      route.post("/users", {
        body: schema.object({ name: schema.string() }),
        handler: (request) => ({ id: "usr_2", name: request.body.name }),
      }),
    ],
  }),
});

const gateway = voke(functions, { config });

const user = await functions.route("GET", "/users/:id", {
  params: { id: "usr_1" },
});

const response = await gateway.request("/users", {
  method: "POST",
  headers: { "content-type": "application/json" },
  body: JSON.stringify({ name: "Ada" }),
});
```

See [Testing](/docs/guides/testing) for test setups.

## Describe a route

`meta` documents a route for generated API documentation, such as the [OpenAPI document](/docs/guides/openapi). The Gateway ignores it when it serves requests:

```ts twoslash
import { schema } from "@vokejs/schema";
import { createFunctions, http, route } from "voke";

const functions = createFunctions({
  orders: http({
    routes: [
      route.get("/orders/:id", {
        meta: {
          summary: "Get an order",
          description: "Reads one order by its id.",
          tags: ["orders"],
          operationId: "getOrder",
        },
        params: schema.object({ id: schema.string() }),
        handler: (request) => ({ id: request.params.id }),
      }),
      route.get("/orders/internal/stats", {
        meta: { hidden: true },
        handler: () => ({ count: 1 }),
      }),
    ],
  }),
});
```

| Field         | Meaning                                       |
| ------------- | --------------------------------------------- |
| `summary`     | A one-line title.                             |
| `description` | A longer explanation.                         |
| `tags`        | Groups for the route.                         |
| `operationId` | A unique, stable name for the operation.      |
| `deprecated`  | `true` marks the route as deprecated.         |
| `hidden`      | `true` leaves the route out of documentation. |

## Add middleware

`voke(functions, { middleware: [...] })` adds Hono middleware to every route of the Gateway, and `route.use(...)` adds it to the routes of one Route Builder. Middleware that reads the body must use `c.req.json()` or `c.req.text()`, so the `body` schema can still read it. Middleware reaches HTTP requests only. To run code around every Function, including invokable and Event Source Functions, or to add a deployed route from a package, write a [Plugin](/docs/guides/plugins).

## Timeout limit on AWS

API Gateway HTTP APIs wait at most 30 seconds for a Lambda integration. A Function with routes therefore cannot have a timeout above 30 seconds: the AWS Provider rejects a larger `synthesis.timeout` or `runtime.timeout` when it synthesizes the stack. Move longer work to an [SQS Function](/docs/guides/sqs-events) or an invokable Function called with `mode: "async"`.
