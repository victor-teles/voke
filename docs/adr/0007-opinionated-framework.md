# Voke is an opinionated framework with one escape hatch per layer

Voke will offer one supported way to do each thing on the path from an empty directory to a deployed API, and will remove alternatives instead of keeping them as options. The goal is to be the easiest AWS Lambda framework to use and deploy; every extra option is a decision the user must make, a combination Voke must test, and a way for two Voke projects to look different. Voke stays neutral about the application itself: which database, auth provider, or architecture a project uses is not Voke's choice.

The supported path is: Bun as the toolchain (pinned in `packageManager`), TypeScript, the Function authoring API from ADR 0005 (`createFunctions`, `fn`, `http`, `sqs`, `route`, `voke`), Standard Schema contracts (ADR 0002), a single ESM bundle built for the Lambda Node.js runtime, API Gateway HTTP APIs with payload format 2.0, CloudFormation as the deployment engine, one stack per stage, the `{ data }` and `{ error }` response envelope, and the AWS Emulator for local resources with Function code running in the local Gateway.

The project entrypoint is the only place Functions are declared. `voke.config.ts` holds project metadata and infrastructure resources and must use a default export; it does not accept a Function Registry. Each setting has one spelling and each API has one name. A project whose entrypoint exports neither a Gateway nor a Function Registry is a configuration error, not a legacy mode.

Each layer keeps exactly one escape hatch for what the supported path does not cover: raw CloudFormation resource definitions in config for infrastructure, Hono middleware on the Gateway for HTTP behavior, per-Function `synthesis` overrides for Lambda settings, `build.external` for bundling, and the `LocalProvider` interface for local emulation. New options should be added only when a use case cannot be met through the default or the layer's escape hatch.

Because the package is unreleased, removals happen without deprecation aliases, as ADR 0005 already decided for the old authoring names. This ADR extends that rule to configuration and CLI surface: the `bun` build target, the config-first Function Registry, the single-function `$default` mode and its `api.function`, `api.routes`, and `handler` settings, the duplicate `cloudFormation.resources` and `cloudFormation.environment` spellings, the `config` named export for config files, the `STAGE` environment fallback, and the `voke experimental` command group are removed. The names ADR 0005 retired but that still exist in source (`defineFunction`, `defineFunctions`, `api`, `createGateway`, `createApiApp`, `routeModule`) are deleted or made internal.

The cost is accepted deliberately. Teams that need a Node-only toolchain, REST APIs, WebSocket APIs, Application Load Balancer targets, or another deployment engine are outside the supported path until Voke adds first-class support for them. An opinion that turns out wrong must be changed in the framework rather than worked around in projects, so opinions that affect deployed behavior should be verified against AWS before they are adopted.
