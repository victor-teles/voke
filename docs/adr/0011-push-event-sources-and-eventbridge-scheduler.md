# Push Event Sources fail the invocation on an invalid payload; schedules use EventBridge Scheduler

`@vokejs/aws` adds three Event Sources next to SQS: `sns({ topic, message, handler })`, `eventBridge({ bus?, pattern, detail, handler })` and `schedule({ expression, timezone?, enabled?, handler })`. Each is its own Function entrypoint and follows the SQS model (ADR "Add SQS Event Sources as a Function entrypoint"): a narrow option surface, one Standard Schema for the application payload, a normalized handler input that keeps the raw provider record as `raw`, local Event Invocation through `functions.sendEvent` with minimal input, and a Voke-owned Lambda adapter. Topics and buses are referenced by Voke resource key. Each Function has exactly one Event Source in v1; the definition's `events` list already allows more, so a plural form can come later without a breaking change.

SNS and EventBridge push one message or one event per invocation, asynchronously. There is no batch, so there is no per-message failure report. An invalid payload (an SNS body that is not JSON or does not match `message`, or an EventBridge `detail` that does not match `detail`) throws an `InvokeError` with code `INVALID_PAYLOAD`, the invocation fails, and Lambda's asynchronous retry and failure handling apply. The handler never sees an invalid payload. Handlers return nothing, and `functions.sendEvent` resolves to `undefined` for them.

Schedules use EventBridge Scheduler (`AWS::Scheduler::Schedule`) and only it. Scheduler evaluates expressions in an IANA time zone with daylight saving, has a much higher quota than the 300 rules per event bus, supports one-time schedules for later, and AWS documents the alternative as "Creating a scheduled rule (legacy)". The costs: each stack gets one IAM role, `VokeSchedulerRole`, that `scheduler.amazonaws.com` assumes (trust limited by `aws:SourceAccount` and the account's default schedule group) with `lambda:InvokeFunction` on exactly the scheduled Functions; the deploying identity needs EventBridge Scheduler permissions and `iam:PassRole`; and the event shape is Voke's. The schedule target's `Input` is a Voke envelope, `{"attempt":"<aws.scheduler.attempt-number>","executionId":"<aws.scheduler.execution-id>","scheduledTime":"<aws.scheduler.scheduled-time>","voke":"schedule"}`, whose placeholders Scheduler substitutes, so the adapter never depends on Scheduler's default payload. An event without the `voke` marker fails the invocation. `AWS::Events::Rule` with a `ScheduleExpression` would need only a rule and a permission, but it is UTC only; ADR "Voke is an opinionated framework" allows one way, so the rule form is not offered.

The shared role needs a stack-level step, so the internal Event Source adapter interface gains an optional `synthesizeStack` member. Synthesis calls it once, after every Function, with every Event Source of that type. Like everything else Function-side, these triggers, permissions and the Scheduler role are absent from the resources-only template that `voke local bootstrap` deploys.

Deferred: one-time `at(...)` schedules, a typed static input per schedule, flexible time windows, per-schedule retry policies and dead-letter queues, Lambda `OnFailure` destinations, plural forms, delivery of emulator events to `voke dev`, and generating these helpers from `serverless.yml` (the migrator only points to them).

Superseded in part by ADR 0020, "Failed events go to a dead-letter queue by default" (`0020-dead-letter-queues.md`).
