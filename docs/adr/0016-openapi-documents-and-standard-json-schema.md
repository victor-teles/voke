# OpenAPI documents come from route contracts through Standard JSON Schema

Voke describes a Gateway's HTTP API as an **OpenAPI Document** (OpenAPI 3.1.0, whose schema dialect is JSON Schema draft 2020-12) generated from the route contracts the project already declares. It ships as `@voke/openapi`, the first first-party Plugin (ADR 0015): `openapi()` in `plugins`, `createOpenApiDocument` for code, and `voke openapi generate [--out] [--server]` for CI. `@voke/openapi` depends on `voke` only, not on `@voke/aws`.

**Standard JSON Schema is the one source of JSON Schema.** `readJsonSchema(schema, "input" | "output")` in `voke` asks `schema["~standard"].jsonSchema[io]({ target: "draft-2020-12" })` (https://standardschema.dev/json-schema), treats a converter that throws as "no JSON Schema" (the specification lets it throw for a schema JSON Schema cannot represent), and falls back to a hand-written top-level `jsonSchema` object. The never-written `~voke.jsonSchema` read is removed without an alias. `@voke/schema` implements the converter for `draft-2020-12` and `draft-07` and throws for other targets and for `schema.undefined()`; Zod 4 implements it natively. The OpenAPI document reads the input side for `params`, `query`, `headers` and `body` and the output side for `output`, and drops the top-level `$schema` of each embedded schema.

**The Function Contract Artifact uses the same reader and narrows the result.** `toContractJsonSchema` is the only place that knows the artifact's subset (`additionalProperties`, `const`, `enum`, `items`, `properties`, `required`, one `type`); it drops other keywords and turns a node using `anyOf`, `oneOf`, `allOf`, `not`, `$ref`, `if` or a `type` array into `true`. Zod and `@voke/schema` contracts therefore get typed entries where they had `true`, so their fingerprints change once and every consumer runs `voke remote generate` once; remote invocation already reports the stale fingerprint as contract drift. Widening the subset stays a separate decision.

**Route documentation is one neutral `meta` field** (`RouteMeta`: `summary`, `description`, `tags`, `operationId`, `deprecated`, `hidden`) next to the route's contract. The Gateway ignores it. Four flat fields would mix documentation with the contract, and a field named `openapi` would put a Plugin's name in core. Every operation documents its success as `200` with the `{ data }` envelope; response status codes and error shapes per route are not part of this decision.

**The document is served only under `voke dev` by default.** An API description is reconnaissance material, so publishing it is an explicit choice: `openapi({ expose: true })` contributes the Plugin Function `openapi-docs`, whose two routes (`/openapi.json`, `/docs`) are `authorizer: "none"` and are deployed. Without `expose`, `runtime.setup` returns a Gateway middleware only when `dev` is true, and nothing reaches the deployed stack. The document is built on the first request and reused, so a route the document cannot describe fails that request only and other Functions pay nothing at cold start.

**The API Reference Page loads Scalar from a pinned CDN URL.** The page is a small HTML string that loads `https://cdn.jsdelivr.net/npm/@scalar/api-reference@<version>` (the standalone browser build, which registers `window.Scalar.createApiReference`) and passes the document URL as escaped JSON. The version is one constant (`1.78.1` when this was written), overridable with `scalar: { version }`. No Scalar or OpenAPI npm package enters the Lambda bundle; the price is that the browser needs network access to jsDelivr, and a version bump needs a manual check of the page.
