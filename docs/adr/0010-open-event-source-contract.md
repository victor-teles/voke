# Event Sources are open records in core and adapters in the Provider

Core used to name SQS in its Event Source types, its model, its error messages and its dev log, and `@voke/aws` treated every Event Source Function as an SQS Function. Adding SNS, EventBridge, schedules, streams or S3 that way would mean editing the provider-neutral core for each one, which the package split forbids (ADR "Split provider and helper ownership into specialized packages").

Core now carries an Event Source as an open record: `{ source, resource?, properties }`, where `source` names the type, `resource` is an optional Voke resource key, and `properties` is a JSON record that core copies to the model untouched. The model holds the same record as `{ type, resource?, properties }`. Core checks structure only: a referenced resource key must exist. The configured Provider checks the resource kind and the properties in its `validate`.

An Event Source Function's handler result is its own. `EventFunctionDefinition` and `EventFunctionHandler` take a result type, and `functions.sendEvent(key, event)` takes the input of that Function's input schema and resolves to what its handler returns. Core has no SQS types, and `fn` no longer accepts `events`. `createFunctions` owns the rules every Provider-built Event Source Function must follow: at least one Event Source, all of one source type, no HTTP routes, and no output schema.

`@voke/aws` keeps one internal adapter per source. An adapter converts the AWS Lambda event to the Event Invocation input, converts the handler result to the Lambda response, validates one Event Source against the model, and synthesizes its CloudFormation resources. The deployed Lambda handler picks the adapter from the Function's first Event Source; validation and synthesis pick it from each Event Source's type. An unknown source is an error, never a skip. The adapter table is internal; a public registration API for third-party sources is a later decision.

SQS behaviour and its CloudFormation output do not change. `sqs()` stores its trigger settings with Lambda's defaults applied (batch size 10, batching window 0, enabled), so the model holds no `undefined` values. Because the package is unreleased, the old shapes are removed without aliases.
